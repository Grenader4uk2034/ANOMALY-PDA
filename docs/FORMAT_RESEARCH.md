# Исследование форматов Anomaly

Документ фиксирует только результаты, которые были проверены на игровых архивах текущей установки. Предположения отдельно отмечены.

## 1. Game Graph

Источник:

`db/configs/spawns.db0` → chunk типа 4 (Game Graph).

Извлечённый размер чанка: 86 177 339 байт.

Проверенные поля заголовка:

| Поле | Значение |
|---|---:|
| Version | 10 |
| Vertex count | 5 345 |
| Edge count | 13 444 |
| Level Point count | 764 226 |
| Level count | 34 |
| Vertex offset | 1 715 |
| Edges offset | 226 205 |
| Points offset | 306 869 |
| GUID | `defae07743cab24b9c71f4729f54e866` |

### Размеры записей

- Edge: `<Hf`, 6 байт.
- Level Point: `<fffIf`, 20 байт.
- Идентификатор уровня в таблице уровней читается как `B` (1 байт).
- Имена секций уровней имеют вид `level01`, `level02` и т. д.

### Проверки целостности

- Количество прочитанных вершин: 5 345.
- Количество рёбер: 13 444.
- Сумма счётчиков рёбер вершин совпадает с заголовком.
- Количество Level Points: 764 226.
- Сумма счётчиков точек вершин совпадает с заголовком.
- Проверки диапазонов записей и ссылок на целевые вершины прошли.

### Предупреждение о расстояниях

Поле `edge.distance` нельзя безусловно трактовать как прямое расстояние между координатами. Для внутрилокационных рёбер оно может представлять игровую стоимость/длину пути; для межлокационных рёбер наблюдалось совпадение с прямым расстоянием.

## 2. Архивы уровней

Обнаружены 34 архива уровней и отдельный `levels.db0`.

Примеры:

- `levels/fake_start/level.ai` в `levels.db0`, размер 14 569 байт.
- `levels/zaton/level.ai` в `level_zaton.db0`, размер 42 578 829 байт.

В архиве Zaton также присутствуют `level.cform`, `level.details`, `level.game`, `level.geom`, `level.geomx`, `level.hom`, `level.ltx` и `level.spawn`.

## 3. Level Graph — статус исследования

Файлы `level.ai` найдены, но полная спецификация бинарного формата пока не установлена.

Для `fake_start/level.ai` первые байты были исследованы, однако трактовка первых полей как версии и количества вершин остаётся гипотезой. Эти значения нельзя использовать в рабочем парсере без дополнительных проверок.

Следующий этап — определить секции файла по реальным структурам и сверить число вершин/рёбер с данными игрового уровня.

## 4. Cross Table — статус исследования

Cross Table необходима для связи локальных графов уровней с глобальным Game Graph. В одном исследованном архиве Zaton файл с очевидным расширением `.gct`, `cross` или `graph` не обнаружен.

Это не доказывает отсутствие таблицы: нужно проверить другие архивы, конфигурационные DB и возможные альтернативные имена/места хранения.

## 5. Инструменты исследования

Использовались Python и инструменты из репозитория stalker-tools, в частности `DBReader.XRReader` для чтения X-Ray DB архивов.

Пример открытия архива:

```python
from DBReader import XRReader

reader = XRReader("/path/to/archive.db0", "xdb")
```

Для больших файлов предпочтительно читать диапазоны непосредственно из буфера архива и не создавать лишние полные копии на диске.
