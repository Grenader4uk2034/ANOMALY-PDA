# Исследование форматов Anomaly

Фиксируются подтверждённые наблюдения по текущему набору игровых архивов. Гипотезы не используются как спецификация.

## 1. Game Graph

Источник: `db/configs/spawns.db0` → chunk типа 4 (Game Graph).

Размер извлечённого чанка: 86 177 339 байт.

| Поле заголовка | Значение |
|---|---:|
| Version | 10 |
| Vertex count | 5 345 |
| Edge count | 13 444 |
| Level Point count | 764 226 |
| Level count | 34 |
| Vertex offset | 1 715 |
| Edges offset | 226 205 |
| Points offset | 306 869 |
| GUID | `defae07743cab24b9c71f4729f54e866` |

### Бинарные структуры

Все структуры читаются в little-endian режиме с фиксированными размерами:

| Структура | Формат | Размер |
|---|---|---:|
| Header | `<BHII16sB` | 28 байт |
| Vertex | `<ffffffBBBBBBBBIIBB` | 42 байта |
| Edge | `<Hf` | 6 байт |
| Level Point | `<fffIf` | 20 байт |

Таблица уровней расположена после заголовка. Запись уровня содержит null-terminated имя, три float координаты, однобайтовый ID, null-terminated section и 16-байтовый GUID.

В записи вершины:
- первые 6 float — level/game координаты;
- первый byte — ID уровня;
- следующие 3 byte — 24-битный `level_vertex_id` в little-endian порядке;
- следующие 4 byte — `vertex_types`;
- далее два uint32 offsets и два byte счётчика.

### Проверки, выполненные в предыдущем исследовании

- Прочитано 5 345 вершин.
- Прочитано 13 444 ребра.
- Прочитано 764 226 Level Points.
- Суммы счётчиков рёбер и точек по вершинам совпали с заголовком.
- Проверки диапазонов и ссылок на целевые вершины прошли.

### Реализация в проекте

Модуль `src/anomaly_pda/game_graph.py` реализует чтение перечисленных структур из уже извлечённого payload чанка Game Graph. Он проверяет границы payload, диапазоны offsets/counts и допустимость целевых вершин.

**Проверка на полном реальном payload новым модулем ещё ожидает запуска в Termux.** Синтетические тесты не заменяют такую проверку.

### Расстояния

Поле `edge.distance` нельзя безусловно считать прямым расстоянием между координатами. Для внутрилокационных рёбер оно может отражать игровую стоимость/длину пути.

## 2. Архивы уровней

Обнаружены 34 архива уровней и отдельный `levels.db0`.

Примеры:
- `levels/fake_start/level.ai` в `levels.db0`, размер 14 569 байт.
- `levels/zaton/level.ai` в `level_zaton.db0`, размер 42 578 829 байт.

В архиве Zaton также присутствуют `level.cform`, `level.details`, `level.game`, `level.geom`, `level.geomx`, `level.hom`, `level.ltx` и `level.spawn`.

## 3. Level Graph

Файлы `level.ai` найдены, но полная спецификация бинарного формата пока не установлена. Исследованные первые байты `fake_start/level.ai` не дают достаточного основания объявлять первые поля версией и количеством вершин.

Следующий этап — определить секции на основе структурных проверок и сверить связи с Game Graph.

## 4. Cross Table

Cross Table нужна для связки локальных графов уровней с глобальным Game Graph. В одном исследованном архиве Zaton файл с очевидным расширением `.gct`, `cross` или `graph` не обнаружен. Это не доказывает отсутствие таблицы: требуется проверить другие архивы, конфигурационные DB и альтернативные имена.

## 5. Инструменты

Для чтения X-Ray DB архивов использовался `DBReader.XRReader` из stalker-tools:

```python
from DBReader import XRReader
reader = XRReader("/path/to/archive.db0", "xdb")
```

Для больших файлов предпочтительно читать диапазоны непосредственно из буфера архива, не создавая лишние копии на диске.
